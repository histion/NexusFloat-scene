## 第十轮（v8.8.9.2）：折线图刻度改整数步长 + 「退出后隐藏最近任务卡片」开关

用户两点需求 + 版本迭代：
1. 折线图「刻度差距太大」→ 指定刻度：充电情况 **电量 20% / 功率 10W / 时间 10 分钟**；
   使用情况 **时间 6 小时 / 电量 20%**
2. 新增开关（用户明确选了「加个开关自己控制」，不是无脑一直隐藏）：开启后最近任务里
   不再出现本软件的卡片
3. 更新日志 + 版本号 → 8.8.9.2

### 根因（旧实现的病灶）
`LineChart` 把 min~max **均分成 4 格**画刻度，所以电量是 0/25/50/75/100、功率是
0/1.25/2.5/3.75/5 这种零碎值；横轴只有「起点/中点/终点」三个标签，粒度太粗。

### 改法（关键设计，下次改图表直接沿用）
- `Chart.kt` 新增 `ChartXTick(ts, label)`；`LineChart` 删 `xLabels`，换 `xTicks`，
  并新增 `leftStep` / `rightStep`（**步长制刻度**，不给步长才退回均分 4 格）
- `axisValues(min, max, step)`：按「step 的整数倍」取刻度，用**整数下标 × step** 算
  （浮点累加会攒误差）。**条数超 `MAX_TICKS(12)` 时必须把步长按整数倍放大
  （10W→20W→30W…），绝不能退回均分 4 格**——退回去刻度又变 35/70 这种零碎数字，
  等于把病带回来了。120W 快充机型（峰值 → 上限 140W）就是这个坑的实例，
  是主理人复核时抓出来的
- `axisTicks(times, stepMs)`：按**本地时间自然边界**对齐（用
  `floorDiv(t - tzOffset, step) * step + tzOffset`），10 分钟刻度落 xx:00/xx:10…，
  6 小时刻度落 00:00/06:00/12:00/18:00；首尾采样点另补并去重
- `layoutXTicks(...)`：**先算位置 → 再画竖网格 → 曲线/图标塔 → 最后画标签**。
  竖网格必须早于图标塔和曲线，否则会盖住曲线。防重叠：首尾必留、中间须与上一个
  保留标签隔 ≥44dp、离右界不足 22dp 的中间刻度丢弃
- 调用点常量：`X_TICK_CHARGE_MS = 10L*60_000L`、`X_TICK_USAGE_MS = 6L*3600_000L`
  （`internal const`，定义在 StatsScreen.kt，StatsDetail.kt 同包直接可用）
- 充电图 `powerMax` 从「按 5W 取整」改成**按 10W 取整**（右轴每 10W 一条，上限不是
  10 的整数倍时最上面那条刻度对不上峰值）
- 删掉 `axisLabels(times)`（三标签版），`fmtClock` 保留给 `axisTicks` 用

### 「退出后隐藏最近任务卡片」开关
- 用户给了三个选项，选了「加个开关自己控制」（默认关）
- 键：`Constants.Modules.KEY_HIDE_RECENTS_ON_EXIT = "hide_recents_on_exit"`
- 双保险：① `OnBackPressedCallback(hideRecentsOnExit)` → `finishAndRemoveTask()`
  （**必须注册在 `setContent` 之前**，否则会盖住统计详情页/应用选择页的 BackHandler）；
  ② `applyRecentsExclusion()` 遍历 `activityManager.appTasks` 调
  `setExcludeFromRecents()`（try/catch 兜底，个别 ROM 会抛）
- 持久化用**新增的 `saveLocalSwitch`**，不走 `saveSwitch`：这条纯属本 App 界面行为，
  SystemUI 用不到，没必要付「写 Remote prefs + fork 一次 root 推 Settings.Global」的代价
- UI 放在首页 `HeaderCard`（跟主题、壁纸同卡），`MainScreen` → `HeaderCard` 透传两个参数

## 第十一轮（v8.8.9.3）：仅亮屏时记录充电联动 + 当前状态卡改版

用户两点需求 + 版本迭代到 8.8.9.3。

### 1. 「仅亮屏时记录」充电期间自动关闭
**先查清的事实（很重要，别再重复排查）**：采样侧**早就**把充电排除在外了——
`BatterySampler.tick()` 原来的判据是 `readScreenOnOnly() && !screenOn && pluggedNow == 0`，
`pluggedNow == 0`（没插电）才跳过。库里 `StatsStore` 也没有任何按 `screen_on` 过滤
采样的地方（只有统计 `screen_on_ms` 用），所以**充电曲线的完整性与这个开关无关**，
夜里的充电曲线本来就不会被它割断。

所以这次做的是「把规则显式化 + 在界面上看得见」：
- `BatterySampler` 把判据提成具名方法 `skipByScreenOnly(screenOn, plugged)`，注释写清
  「充电期间恒不跳过」以及为什么（跳过的代价是整夜充电只剩零星几点 → 样本太少被判
  无效会话直接删掉 → 充电记录全没）
- `StatsScreen` 新增 `readChargingNow(context)`：读 `ACTION_BATTERY_CHANGED` 的
  **粘性广播**（`registerReceiver(null, filter)`，不注册、不用注销）。不复用采样数据，
  因为采样点默认 15 秒一个、统计关掉时一个都没有，而开关要立刻反映状态
- `StatsScreen` 里 `val chargingNow = remember(refreshTick) { readChargingNow(context) }`，
  跟着本来就有的 5 秒刷新重读，插拔电源最迟 5 秒内反映；页面切走就不再读
- 设置卡里那一行：`checked = screenOnOnly && !charging`、`enabled = !charging`，
  副标题在充电时说明「充电中已自动关闭…拔电后恢复为「开」」
- **关键设计：充电期间绝不改写用户的 prefs 值**。「恢复原本状态」因此是天然成立的。
  写成「先存原值 → 改掉 → 充电完写回来」的话，进程在充电中途被杀就永久丢了用户的选择

### 2. 「当前状态」卡片改版
- 删掉电量旁边那行小字（`功率 · 电压 · 温度` 的 buildString），只留「充电中/使用中」
- 新增「电压」一格，与电流、功率、电池温度并排成 **4 格**（顺序：电流 / 电压 / 功率 / 电池温度）
- 4 格后每格只剩 ~70dp，19sp 的「178 mA」会折行、四块高度对不齐 → `MetricTile` 新增
  `compact: Boolean = false`：内边距 14→8dp、标题 11→10sp、数值 19→14sp，且
  `maxLines = 1` + `softWrap = false`（窄屏宁可省略号，不能让高度对不上）。
  默认 false，其它调用点（充电详情/使用周期/累计那几处三格布局）不受影响
