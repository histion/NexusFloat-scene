## 第十二轮（v8.8.9.4）：修复充电功率曲线断续（假 0 采样）+ 统计页拆成「充电/使用」两模块

用户两点需求 + 版本迭代到 8.8.9.4。

### 1. 假 0 采样（充电功率曲线断续）
**病灶**：读不到电流/功率的采样点被原样落库成 `power_w=0`。曲线表现为「多数点贴 0、
偶尔窜一根 ~50W 尖峰」，平均功率被系统性拖低（用户截图：平均 20.3W vs 峰值 52.9W）。

**改法**（关键设计）：
- `PowerTracker` 加 `lastFresh` / `lastWasFresh()`：各返回路径标记「是否本拍新读到」。
- `BatterySampler` 加 `lastValidCurrentA` / `chargeCarryTicks`：充电时读不到就沿用上次
  有效电流，上限 `Constants.Battery.CHARGE_CARRY_MAX_TICKS = 40` 拍；沿用值仍写进
  `power_w`/`current_ma`（充电积分继续用），但 `s.powerKnown = currentFresh || (!carriedCurrent && powerTracker.lastWasFresh())`；拔电 `chargeCarryTicks` 归零。
- `Constants.Battery.CURRENT_MAX_A` 12f → 20f（不再把 >12A 真快充当非法值丢）。
- `Stats.DB_VERSION` 1 → 2；`samples` 新增 `power_known INTEGER NOT NULL DEFAULT 1`。
- `StatsStore.aggregate()` 平均功率改 **dt 加权 + 只算 power_known=1**，峰值也只取已知点；
  `queryAppUsage()` 同口径。
- `StatsScreen.chargePowerSeries()`：未知点用**前一个有效值桥接**（不画假 0、不留空洞），

## 第十三轮（v9.0.0.0）：新增「帧记录」页（悬浮球 + 按次帧率记录）

用户需求：底部新增第 5 个页签「帧记录」，对标截图（图一/图二）但保持本软件自己的风格。

### 结构（新增 frame 包，与 stats 平行）
- `frame/FrameRecordStore.java`：独立库 `nexus_frames.db`（v1，records+samples 两表）。
  **刻意不塞进统计库**——频率差 15 倍、字段不重叠，且「清空统计数据」不该误伤帧记录。
  汇总放 SQL 重算（同 StatsStore 思路）；进行中的记录页面刷新时也刷汇总。
- `frame/FrameSampler.java`：1 秒一拍，取数全部复用现成读取器（面板/SF latency/
  TimeStats/FPSGO/GED 按「高级」页开关走；/proc/stat 做 CPU 占用；policy 读各簇频率；
  GpuRootReader 读 GPU；CpuTempReader 读温度；PowerTracker 算功率）。
  **不退回 Choreographer**——那是屏幕刷新率，记游戏帧率等于记假数据。
  fps 语义三态：>0 实测 / 0 画面静止 / **-1 读不到**（曲线留空不画 0，
  沿用 v8.8.9.4 的教训）。
- `frame/FrameBubble.java`：SYSTEM_ALERT_WINDOW 悬浮球（自绘 View，无布局文件）。
  棕黄 0xFFB8860B 未记录 / 红 0xFFE53935 记录中 + 闪烁环 + 实时帧率；
  点按切换、可拖动（位置存 prefs）、长按收球。权限先 root `appops set` 静默授，
  不行才跳设置页。
- `frame/FrameRecordService.java`：前台服务（specialUse）托悬浮球+采样，
  通知实时显示应用名和近几拍均帧。
- `ui/FrameRecordScreen.kt`：一级页（设备信息卡 + 记录列表 + **自滚动 + 固定底部操作条**）
  与二级页（备注 + 汇总 + 8 张曲线）。二级视图同页替换 + BackHandler，同统计页。
  复用 `SectionCard/MetricTile/EmptyHint/appIcons/axisTicks/LineChart`（全 internal 同包）。

`MainScreen` 里帧记录页**整页接管**：`if (tab == MainTab.FRAMES) FrameRecordScreen(weight(1f))`
else 原有的滚动 Column——因为操作条要钉在页底，塞进整页滚动里做不到。
`when(tab)` 补了 `FRAMES -> {}` 空分支让枚举穷尽。

### 踩过的坑（都修掉了）
1. **悬浮球点按在主线程做重活**（root dumpsys + SQLite 插入）→ 游戏 ANR。
   改成：状态位先翻（球立刻变红）、重活 post 到采样线程；tick 见 recordId 未建好就跳过。
2. **先清 recordId 再 flush** → 缓冲里最后一批采样点被丢。必须先 flush 后清 id。
3. **finalizeOrphans 会把「正在进行」的记录也收口**（页面一刷新就毁掉进行中的记录）。

4. **删除进行中的记录**：采样器还会继续写孤儿点、球一直红着。加
   `discardRecording()`（丢弃不收尾）+ Listener `onRecordingChanged` 回调联动悬浮球。
5. Math.ceil/floor 只收 Double（Kotlin 不做 Float→Double 隐式提升）。
6. `CpuTempReader` 泛化成 CPU/GPU 双 zone（各自独立的缓存与退避计数，
   共用计数会让先失败那个把另一个拖进退避）。

## 第十四轮（9.0.0.0 覆盖更新）：修复帧记录汇总错位 + 四项真机反馈

真机反馈，版本号不变（覆盖更新），内容合并进 9.0.0.0 日志。

### 核心 Bug：汇总数值整体错位（用户看到「平均帧率 655」）
**根因**：`FrameRecordStore.refreshAggregates` 的 SQL 输出了 13 列，比读取端多一列
`SUM(CASE WHEN fps>0 THEN 1...)`（有效点数），导致从 avg_fps 起整体右移一列——
655 其实是「有效采样点数」，不是帧率。
**修法**：删掉那列，SQL 恢复 12 列，**SQL 每列 + 读取端每个 cv.put 都标 `// idx0..idx11`**
序号注释，防止再加列再次错位（这坑很隐蔽，以后加聚合列务必双端同步标号）。
**存量修复**：DB_VERSION 1→2，onUpgrade `oldVersion<2` 时 `fixAggregateMisalignment(db)`
逐条重算全部记录。关键：迁移必须**复用 onUpgrade 传入的连接**（不能重入
getWritableDatabase()，会在升级事务里卡死）——所以 refreshAggregates 拆成
public 单参（自取连接）+ private 双参（复用连接）两个重载。

### 其余三项（体验）
- 悬浮球 52dp 圆 → **44×22dp 胶囊**（drawRoundRect，圆角=半高），默认字 "fps"，
  记录中显示实时帧率；闪烁环沿矩形描边。拖动/点按/长按/位置存取逻辑未动。
- `FrameRecordService` 加 `serviceRunning`(volatile)+`isRunning()`；底部「+」变开关：
  未跑→拉起流程，在跑→stop（进行中的记录会保存）。
- `MetricTile` 加 `icon: String?=null`（默认 null，既有调用点全部具名参数不受影响）；
  DeviceCard 三格 🧠/📱/🤖；筛选下拉加 `leadingIcon` 应用图标（appEntryIcons 单独按
  appEntries 取）；`appIcons` 加 `LruCache<String,ImageBitmap>(64)` 进程级缓存
  （原来页面 3 秒刷一次就重解码一轮全部图标）。

## 第十五轮（v9.0.0.1）：帧记录 5 项反馈修复

用户 5 点反馈 + 版本迭代到 9.0.0.1。

### 1. CPU 占用恒 0%（核心 bug）
**根因**：`FrameSampler.readProcStat()` 用 `line.startsWith("cpu")` 宽松匹配 + 靠文件
出现顺序填 List，一旦中间插进别的行（部分 ROM 的 cpuacct 等）整机行就不在下标 0，
做差时分母分子对不上 → 占用恒 0。
**修法**：改成明确解析——整机行按 `id.equals("cpu")` 认放下标 0，核行按 `Integer.parseInt(id.substring(3))`
取核号归位到下标 N+1；返回时用 List 收集非 null 槽（核号不连续也不 NPE）。
基线逻辑提成 `storeBaseline()`，第一拍建基线、之后做差。

### 2. 删两张曲线
详情页删「内存 (GB)」「电量 (%)」两张图；`FrameRamColor`/`FrameBatteryColor` 顶层 val 一并删
（否则 unused 告警）。

### 3. GPU 频率刻度动态化
50MHz 步长；0 坐标 = 本次 GPU 最低频率再往下 10MHz（`minFreq-10` 向下取整到 50），
曲线落在轴中段不从 0 空上来。判断依据：min/max 遍历只是对已加载 samples 数组的纯内存
运算，无额外 IO/sysfs，**无额外功耗**，故采用动态调整而非固定 50 起步。

### 4. 功耗刻度 0.5W
step 固定 0.5f，上限峰值 1.1 倍向上取整到 0.5；leftFormat 对整数显示整数、小数显示一位。

### 5. 汇总卡加「总时间」
第三行第 1 格加「总时间」，复用 `fmtDuration`（已支持到秒：m<10 时「X分Y秒」，纯秒「X秒」）。

### 产物
- versionCode 9000001 / versionName 9.0.0.1
- CHANGELOG.md + MainActivity CHANGELOG 列表新增 9.0.0.1 条目；README「八、帧率记录」标题
  改 9.0.0.1、曲线数 8→6 张、去掉内存/电量描述
- 本轮直接改（未走团队），改动文件：FrameSampler.java、FrameRecordScreen.kt、
  app/build.gradle.kts、CHANGELOG.md、MainActivity.kt、README.md

### 注意

  都按 `times.length` 动态取核数，不再假设 16 核。
